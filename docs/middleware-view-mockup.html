설계 메모 — 확정 전에 맞출 것

여섯 번째 보기 “미들웨어”의 목업이다. 기존 시작 흐름 보기가 “Program.cs에 무엇이 등록돼 있나”를 소스 순서대로 보여준다면, 이 보기는 “요청 하나가 실제로 무엇을 통과하고, 어디서 끊기고, 응답이 돌아올 때 무엇이 더 실행되나”를 보여준다. 미들웨어를 처음 보는 사람이 제일 헷갈리는 것이 돌아오는 길과 단락(short-circuit)이라, 그 둘을 화면의 중심에 뒀다.

1. 이 보기가 답하는 질문

  • 요청이 어떤 순서로 무엇을 통과하는가 — 그리고 응답은 역순으로 무엇을 더 거치는가
  • 어디서 끊길 수 있는가(401 · 429 · 503 · 400), 끊기면 무엇이 실행되지 않는가
  • 각 미들웨어가 HttpContext의 무엇을 읽고 무엇을 쓰는가(Items · Headers · User)
  • 이 엔드포인트에는 실제로 무엇이 적용되는가(UseWhen · 라우트 그룹 · 필터까지 합쳐서)
  • 등록만 하고 실행되지 않는 미들웨어가 있는가

2. 화면 구성 — 하위 보기 4개

  • 파이프라인 — 등록 순서대로 세운 세로 지도. 카드마다 요청 시/응답 시 두 줄로 나눠 적고, 단락은 오른쪽으로 빠지는 빨간 가지로 표시한다.
  • 엔드포인트별 — 진입점 × 미들웨어 매트릭스. ● 적용 / ○ 조건부 / · 미적용.
  • 단락 지점 — 끊기는 자리마다 “실행되지 않는 것”과 “그래도 실행되는 응답 후처리”를 나란히 놓는다.
  • 점검 결과 — 순서·구성 규칙에 걸린 항목 표.

3. 무엇을 정적으로 읽어내나

  • 순서 — app.UseXxx()/app.Use(...) 호출 순서(시작 흐름 보기가 이미 읽고 있다).
  • 요청/응답 구간 — InvokeAsync 본문에서 await _next(context) 호출을 기준으로 앞뒤를 나눈다.
  • 단락 — _next를 부르지 않고 끝나는 분기. 그 분기에서 StatusCode에 넣는 상수를 응답 코드로 읽는다.
  • 읽기/쓰기 — context.Items[...], Response.Headers[...], context.User 접근을 모아 카드에 붙인다.
  • 조건부 적용 — UseWhen/MapWhen의 조건식과 env.IsDevelopment() 같은 분기.
  • 필터 — [Authorize], 액션 필터, AddEndpointFilter까지 이어 붙여 엔드포인트 파이프라인을 만든다.

4. 못 읽는 것 — 솔직하게 표시한다

  • 런타임 설정으로 갈리는 분기(if (_options.Enabled))는 조건부로만 표시하고 값은 모른다고 적는다.
  • IStartupFilter·라이브러리가 몰래 끼워 넣는 미들웨어는 어셈블리 안이라 안 보인다. “여기에 프레임워크가 더 넣을 수 있다”는 자리만 알려준다.
  • 같은 이름의 Use... 확장이 여러 개면 어느 것인지 심볼로 확정하고, 실패하면 후보를 나열한다.

5. 점검 규칙 초안

미들웨어는 “순서가 곧 동작”이라 규칙 대부분이 순서·위치 검사다. 추정으로 표시된 것은 조건식 값을 모르는 경우다.

규칙내용심각도판정

6. 기존 보기와의 연결

  • 시작 흐름 — 등록 순서는 거기서 읽은 것을 그대로 쓴다. 시작 흐름의 app.UseXxx() 줄을 누르면 이 보기의 해당 카드로 온다.
  • DB · 캐시 — 미들웨어가 여는 저장소 접근(레이트리밋의 INCR, 세션 검증의 GET)도 같은 규칙으로 검사해 양쪽에 함께 띄운다.
  • 호출 흐름 — 미들웨어 카드에서 “이 안의 호출 흐름 보기”로 넘어가면 InvokeAsync부터의 그래프를 그린다.

확인이 필요한 것

  • 미들웨어 작성 방식 — 규약 기반 클래스(InvokeAsync)인가, IMiddleware 구현인가, 인라인 app.Use(async (ctx, next) => ...)인가? 셋 다 읽지만 우선순위를 알고 싶다.
  • 필터도 같이 볼지 — 액션 필터·엔드포인트 필터까지 한 지도에 그릴지, 미들웨어만 그릴지. 목업은 “엔드포인트 안쪽”으로 접어서 함께 그렸다.
  • 보고 싶은 것이 어느 쪽인가 — “새로 온 사람이 구조를 파악”이 목적인지, “순서 실수를 잡는 점검”이 목적인지에 따라 기본 화면을 다르게 두겠다.
  • 미들웨어가 사내 공통 라이브러리에 있다면 그 어셈블리도 솔루션에 포함되는가? 아니면 이름만 보이고 내부는 못 읽는다.
