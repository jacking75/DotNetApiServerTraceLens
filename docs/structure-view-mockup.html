설계 메모 — 확정 전에 맞출 것

보기 전환 버튼(호출 흐름 / 클래스 다이어그램 / 전체 흐름도)을 툴바로 올리고, 클래스 보기를 솔루션 전체 클래스를 한 번에 그리는 UML 클래스 다이어그램으로 바꾼 목업이다. 데이터는 가짜지만 보기 전환·네임스페이스 필터·관계 종류 토글·줌·1홉 포커스·클릭 상세는 실제로 동작한다.

1. 클래스 다이어그램

모든 클래스를 UML 박스(이름 / 필드 / 메서드 3단)로 한 캔버스에 그리고, 네임스페이스를 점선 패키지 박스로 묶는다. 관계는 네 종류를 선으로 구분한다.

  • 상속 — 실선 + 빈 삼각형
  • 구현 — 점선 + 빈 삼각형
  • 연관 — 실선 화살표(필드로 들고 있는 타입, 곧 DI 주입)
  • 의존 — 점선 화살표(메서드 호출·파라미터, 지금 그래프의 호출 엣지)

왼쪽 네임스페이스 목록은 체크박스로 패키지 단위 표시/숨김, 이름 클릭은 그 패키지로 스크롤 + 선택이다.

2. 전체를 그리되 커지면 줄이는 장치

전체를 한 화면에 그리는 게 목적이라 노드 수를 줄이는 대신 보는 밀도를 조절하는 손잡이를 뒀다.

  • 멤버 표시: 필드 / 메서드 각각 끄기(이름만 남기면 박스가 확 작아진다)
  • 관계 종류 끄기: 의존(호출)만 꺼도 선이 절반으로 준다
  • 줌 50 / 75 / 100 / 맞춤
  • 네임스페이스 체크박스, 선택 1홉만 토글

패널 사이 경계선을 드래그하면 3분할 폭이 바뀌고(더블클릭하면 기본값 복귀), 창을 키우면 그만큼 다이어그램 영역이 넓어진다. 높이도 창 높이를 따라간다.

3. 전체 흐름도(그대로)

기본 화면은 컨트롤러 박스에 라우트가 줄로 붙은 클래스 단위 지도이고, 라우트 줄을 누르면 그 진입점의 메서드 단위 전 구간 흐름으로 들어간다. 깊이 제한을 넘는 호출은 줄 오른쪽에 +n으로 남긴다.

확인이 필요한 것

  • Analyzer에 새 데이터가 필요하다. 지금 graph.json에는 호출 엣지와 클래스 위치만 있다. 클래스 다이어그램을 그리려면 인터페이스(현재 classes에서 제외), 필드·프로퍼티(이름·타입·접근제한자), 메서드의 접근제한자·반환타입, baseType/interfaces가 있어야 한다. 스키마 v4로 올리고 Analyzer/Server/client를 함께 고치는 작업이다.
  • CLAUDE.md 제약 1번("전체 그래프를 한 화면에 그리지 않는다")을 클래스 다이어그램에 한해 푸는 것으로 문서를 고칠지.
  • 기본으로 켤 관계 종류. 지금은 상속·구현·연관은 켜고 의존(호출)은 꺼 두었다.
  • 필드에 DTO·기본 타입(Guid, string)까지 다 보여줄지, 솔루션 안 타입만 보여줄지.
  • 클래스가 수백 개인 사내 코드에서 전체 렌더가 버티는지. 필요하면 멤버를 접은 상태로 먼저 그리고 선택한 박스만 펼치는 쪽으로 간다.
