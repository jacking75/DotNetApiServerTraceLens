설계 메모 — 확정 전에 맞출 것

요청한 두 가지(① 클래스 구조도 보기 버튼, ② 진입점 기준 전체 흐름 구조도)를 기존 화면에 어떻게 얹을지 그린 목업이다. 데이터는 가짜지만 보기 전환·네임스페이스 선택·노드 클릭·깊이 조절은 실제로 동작하니 눌러보고 형태를 정하면 된다.

1. 보기 전환 버튼을 툴바로 올렸다

왼쪽 패널의 진입점/클래스 탭을 없애고 화면 전체를 바꾸는 3분할 스위치를 위에 뒀다. 보기를 바꾸면 왼쪽 목록·가운데 그래프·breadcrumb·상세 패널이 한 세트로 같이 바뀐다.

  • 호출 흐름 — 지금 쓰던 화면 그대로(진입점 → 단계식 드릴다운)
  • 클래스 구조도 — 네임스페이스 지도 → 네임스페이스 안 클래스 구조도
  • 전체 흐름도 — 진입점 전체 지도 → 진입점 하나의 전 구간 흐름

2. 클래스 구조도는 두 단계

왼쪽에 네임스페이스를 두고 누르면 그 안 클래스 구조도를 그린다. 아무것도 안 고른 기본 화면은 네임스페이스끼리의 의존 지도라서 "이 솔루션이 몇 겹인가"를 먼저 본다.

내부 구조도에서는 밖으로 나가고 들어오는 관계를 점선 그룹 박스로 접어 두고, 그 줄을 누르면 그 네임스페이스로 이동한다. 그래서 한 화면에는 항상 네임스페이스 하나만 있다.

3. 전체 흐름도도 두 단계

기본 화면은 컨트롤러 박스에 라우트가 줄로 붙은 클래스 단위 지도다. 라우트 줄을 누르면 그 진입점의 메서드 단위 전 구간 흐름으로 들어간다.

호출 흐름 보기의 단계식 드릴다운과 달리 여기서는 한 진입점의 끝까지를 한 번에 펼치고, 대신 클래스 단위로 묶어 박스 수를 줄인다. 깊이 제한을 넘는 호출은 줄 오른쪽에 +n으로 남긴다.

확인이 필요한 것

  • CLAUDE.md 제약 1번은 "전체 그래프를 한 화면에 그리지 않는다"인데 이번 요청은 그 반대다. 목업처럼 네임스페이스/진입점을 포커스 단위로 삼아 전체를 계층으로 쪼개는 절충으로 갈지, 아니면 제약 자체를 푸는 것으로 CLAUDE.md를 고칠지.
  • 클래스 구조도에서 DTO(Contracts)·유틸(Common)을 기본으로 숨길지. 지금은 툴바 토글로 넣어 뒀다.
  • 전체 흐름도 기본 깊이(지금 3). 실제 사내 코드 기준으로 몇이 적당한지.
  • 클래스 박스에 메서드 줄을 몇 개까지 보여줄지(지금 6개 + +n).
