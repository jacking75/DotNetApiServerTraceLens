- [x] 첫 실행·분석·검색·선택·비교·오류 복구 흐름의 코드를 점검한다.
- [x] 검색 결과와 현재 선택을 이해하고 복구할 수 있도록 진입점 목록을 개선한다.
- [x] 통합 찾기의 키보드 조작과 최근 검색 표시를 개선한다.
- [x] 경로 선택의 잘못된 확정과 메뉴의 포커스 유실을 수정한다.
- [x] 재분석 실패·취소 후 비교를 막고 분석 작업 피드백을 보강한다.

- [x] 라이트 테마의 분석 버튼과 활성 탭 글자 대비를 개선한다.

- [x] 회귀 테스트·빌드·실제 브라우저 확인을 마친다.

## 점검 방법과 범위

저장소의 설계 제약과 데이터 계약을 기준으로 첫 화면, 대상 선택, 여섯 보기, 진입점 목록,
통합 찾기, 소스·AI 문맥, 신선도, 분석 전후 비교를 코드에서 추적한다. 로컬 OrderApi 예제로
실제 브라우저 조작과 화면을 추가 확인한다. 실제 사용자를 관찰한 연구 결과는 아니다.

## 발견한 문제와 수정 방향

| 우선순위 | 관찰 근거 | 사용자에게 미치는 영향 | 수정 방향 |
|---|---|---|---|

| 높음 | `PathPicker`의 더블클릭이 폴더 모드도 파일을 반환한다 | 원본 소스 루트 연결에 잘못된 경로가 전달된다 | 폴더 모드에서 파일 확정을 막는다 |
| 높음 | 경로 탐색 중 이전 `chosen`이 유지된다 | 이동 중에 이전 폴더나 파일을 확정할 수 있다 | 로딩·오류 상태에서는 확정을 막고 선택을 초기화한다 |
| 높음 | OrderApi의 네 갈래 호출을 1366×768에서 확인하면 노드가 겹친다. `spacingFactor: 0.5`가 배치 간격을 상자 크기 이하로 줄인다 | 메서드 이름과 호출 화살표를 구별하기 어렵다 | 겹침을 방지하는 간격으로 배치하고 캔버스 맞춤 배율을 적용한다 |
| 중간 | `EntryPointList`가 검색창에서 올라온 Home·End·방향키도 처리한다 | 검색어를 편집하다 포커스가 목록으로 이동한다 | 실제 목록 항목에서만 목록 키를 처리한다 |
| 중간 | 필터 결과가 0개여도 “솔루션을 분석하면…”이라고 표시한다 | 이미 분석한 사용자가 재분석을 시도하게 된다 | 전체 대비 표시 건수, 검색 결과 없음, 초기화 동작을 제공한다 |
| 중간 | 외부에서 선택한 진입점이 검색·숨김 조건에 가려질 수 있다 | 현재 어디를 보고 있는지 목록에서 찾기 어렵다 | 가려진 선택 안내와 현재 선택 표시 동작을 제공한다 |
| 중간 | `QuickFind`의 모달 전체 Enter 핸들러가 `flat[active]`를 선택한다 | Tab으로 이동한 버튼과 다른 결과가 열릴 수 있다 | 입력창과 결과 버튼의 키 처리를 분리하고 실제 포커스를 이동한다 |
| 중간 | 통합 찾기 최근 목록이 저장된 ID를 그대로 표시한다 | 긴 식별자를 읽어야 하고 사라진 결과도 남는다 | 현재 그래프로 이름을 복원하고 없는 항목은 제외한다 |
| 중간 | 통합 찾기에 눈에 보이는 닫기 버튼이 없다 | Esc나 바깥 클릭을 모르는 사용자가 닫기 어렵다 | 제목·닫기·결과 수·검색 초기화를 제공한다 |
| 중간 | 헤더 메뉴가 내부 클릭을 모두 닫기로 처리한다 | 언어 선택 같은 폼 조작 중 메뉴가 사라지고 포커스가 유실된다 | 실행 항목만 닫고 Escape·외부 이동·키보드 탐색을 처리한다 |
| 높음 | 라이트 테마에서 강조 배경 `#0f6ea8` 위에 글자 `#346fb1`을 쓴다 | 분석 버튼과 현재 보기 탭의 글자를 읽기 어렵다 | 흰색 글자로 바꾸고 두 테마의 강조 버튼 대비를 검사한다 |
| 중간 | Minimal API 람다를 선택한 뒤 클래스 보기로 이동하면 화면에 없는 Program을 기준으로 모든 클래스를 흐리게 한다 | 전체 구조를 읽기 어렵다 | 선택 클래스가 실제 배치에 있을 때만 관련 없는 클래스를 흐리게 한다 |

## 유지할 사용자 흐름

- 첫 화면의 예제 분석, 대상 직접 선택, 지원 범위와 학습 절차는 유효한 시작 경로다.
- 분석 단계·취소·서버 재접속, 신선도 배지와 수동 재분석은 유지한다.
- 호출 흐름은 진입점 하나를 중심으로 탐색한다. 전체 다이어그램의 밀도·관계·범위 조절도 유지한다.
- 소스 위치, 근거, 추정 표시, AI 문맥 미리보기는 결과를 검토하는 데 필요한 정보다.
- 분석되지 않은 영역과 미지원 기술은 진단에서 계속 드러낸다.

## 검증 결과

- `npm run lint`가 통과했다.
- `npm test`의 27개 파일, 149개 테스트가 통과했다. 입력 키 가로채기, 실제 포커스 결과 선택,
  최근 결과 복원, 폴더 모드, 탐색 중 확정 방지, 메뉴 언어 선택과 포커스, 분석 실패·취소·연결 종료,
  비교 중단, 분기 4개·12개의 노드 겹침, 강조 버튼 대비, 보기에 없는 클래스 선택을 확인했다.
- `npm run build`의 타입 검사와 프로덕션 빌드가 통과했다. 주 번들이 약 511kB라 Vite의 500kB 초과
  안내는 남아 있다. 이번 변경에서 경고 기준을 높이거나 숨기지 않았다.
- `dotnet build TraceLens.sln --no-restore --nologo`가 경고 0개·오류 0개로 통과했다.
- `dotnet test TraceLens.sln --no-build --nologo`에서 Analyzer 104개, Server 121개, Mcp 17개,
  Cli 15개로 총 257개가 통과했다.
- 로컬 Chrome에서 OrderApi를 실제 분석하고 진입점 8개를 확인했다. 검색 초기화, 입력창 Home,
  통합 찾기 방향키·Enter·최근 항목, 메뉴 한국어/영어 전환·Escape 복귀, 경로 선택을 조작했다.
- 여섯 보기를 라이트 1366×768, 다크 1600×950의 총 12개 조합으로 열고 화면을 확인했다.
  호출 흐름의 실제 노드 경계 겹침, 페이지 전체 가로 넘침, 자바스크립트 실행 오류가 없음을 확인했다.
  마지막 클래스 흐림 수정 후에도 브라우저에서 흐려진 박스가 0개인 것을 확인했다.

## 한계와 후속 확인

- 사용자가 실제 업무 중 어디서 막히는지는 소규모 사용자 관찰이 필요하다. 이번 검증으로 학습 시간이나
  업무 효율의 향상 수치를 주장하지 않는다.
- 큰 그래프는 맞춤 배율에서 글자가 작아질 수 있다. 확대·패널 접기·단계별 탐색을 함께 사용한다.
- 1040px 미만 화면, 스크린 리더 실기기, macOS·Linux는 이번에 검증하지 않았다.
- 그래프 스키마나 서버 API 계약은 변경하지 않았다.
